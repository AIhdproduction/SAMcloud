# UI language (German / English)

The web interface is available in German (default) and English. All visible
texts come from one translation module; the processing engine, project files
and exported products are language-neutral and do not change with the UI
language.

## Choosing the language

The active language is resolved in this order (first valid value wins):

1. **User choice** in *Settings*, card *Sprache / Language*. It is saved
   immediately in `.samcloud/user_preferences.json` (key `ui_language`) in the
   SAMcloud folder. The file is local and listed in `.gitignore`.
2. **Configuration default** `application.language` in `config/defaults.yml`
   (`de` or `en`, shipped as `de`).
3. **Built-in default** `de` (`DEFAULT_LANGUAGE`).

An invalid or unsupported value is ignored with a log warning, and the next
level applies (user, then config, then `de`). Regional spellings such as
`DE`, `de-CH` or `en_US` are normalised to `de` / `en`; a missing or broken
preferences file counts as "no choice".

Changing the language in the settings page applies it at once: the page
reloads in the new language and unsaved inputs of the settings form are kept
(they are restored after the reload, only for the same project). **Reset to
configured default** removes the stored choice, so `application.language`
applies again. The choice is global for the local installation; running jobs
and the projects themselves are not affected.

## What is translated

Only text that is shown in the browser: page titles, navigation, buttons,
labels, notifications, viewer toolbars and status lines, and the display of
stored messages (progress stages, AprilTag report warnings, viewer server
messages). Class names are translated for display through the `classes.*`
keys.

Not translated, and identical in both languages:

- internal IDs, status codes, class names and LAS/Cyclone class codes,
- API field names of the REST endpoints,
- project files (`project.samcloud.yml`, JSON reports), `progress.json`,
  `run_summary.txt` and the logs,
- the LAS, PLY and DXF output (layer names, labels).

Stored texts such as the progress stage keep their English engine wording on
disk; the UI translates them only when it displays them, so a project
processed in one language reads correctly in the other.

## How it works

The module is `samcloud/app/i18n.py`:

| Function | Purpose |
|---|---|
| `t(key, **params)` | Text of `key` in the current language; `str.format` placeholders (`{count}`) are filled from `params`. |
| `translate_or(key, fallback, **params)` | Like `t`, but returns `fallback` when no catalogue knows the key. Used for keys built from data, for example `translate_or(f"classes.{name}", name)`. |
| `current_language()` | Active language code (cached). |
| `set_language(code)`, `clear_user_language()` | Store or remove the user choice (atomic write of the preferences file). |
| `SUPPORTED_LANGUAGES` | Supported codes and their display names: `{"de": "Deutsch", "en": "English"}`. |

Lookup falls back from the current language to English and finally to the
key itself; it never raises, so a missing key shows up as its key name instead
of breaking a page.

The catalogues are JSON files in `samcloud/app/locales/<language>/`, one file
per namespace (`app`, `classes`, `common`, `control_points`, `dense`, `dxf`,
`dxf_ui`, `gcp_review`, `home`, `nav`, `preview`, `processing`, `projects`,
`settings`, `sparse`, `targets`, `viewer`, `workflow`). Nested objects become
dotted keys: `"language": {"title": ...}` in `settings.json` is the key
`settings.language.title`.

## Adding or changing a text

1. Add the key to **both** `locales/de/<namespace>.json` and
   `locales/en/<namespace>.json`. Both languages must have identical key sets
   and the same placeholders.
2. Use it in the page code with `t("namespace.key")` (or
   `translate_or(...)` for data-driven keys). Never translate values that are
   stored or compared in code; translate only where the text is displayed.
3. For a new class in `config/classes.json`, add a `classes.<name>` entry.

## Adding a language

1. Create `samcloud/app/locales/<code>/` with the same namespace files and
   keys as `en/`.
2. Add the code and its display name to `SUPPORTED_LANGUAGES` in
   `samcloud/app/i18n.py`. It then appears in the settings selector and is
   accepted for `application.language`.

## Tests

`tests/test_i18n.py` enforces the rules: identical key sets and placeholders
in `de` and `en`, no empty values, a `classes.*` key for every configured
class, every literal key used in `samcloud/app` present in the English
catalogue, the resolution order and fallbacks, and the display-only
translation of stored texts. `tests/test_i18n_settings.py` covers the
settings card (language change keeps unsaved values, reset to the config
default, saving settings is independent of the language).

All tests run with the English UI: an autouse fixture in `tests/conftest.py`
forces `en` and redirects the preferences file to a per-test location, so the
real `.samcloud/user_preferences.json` is never touched. Tests that assert
German wording use the `german_ui` fixture or call `use_language(monkeypatch,
"de")`.
